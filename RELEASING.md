# Releasing

Installed users only receive changes when `version` in `.claude-plugin/plugin.json` changes, so every release needs a version bump. That file is the only place the version number lives.

## While developing

- Commit to `main` as normal. **Don't change the version** in feature commits.
- Add an entry for each user-visible change under `## Unreleased` at the top of `CHANGELOG.md`.

## Choosing the version number

| Bump | When | Examples |
|---|---|---|
| **Patch** (1.7.1) | Fixes and wording changes that don't alter behaviour | A typo in a reference file, a checker bug |
| **Minor** (1.8.0) | New options, audiences, agents or checks; existing runs keep working | A new audience preset, a new `briefing` format |
| **Major** (2.0.0) | Anything that breaks existing users | Renamed or removed options, a changed output layout, a new `_generation.json` format that `/update` can't read |

If the `_generation.json` format changes, bump its `schema` field and either make `/codebase-tutorial:update` handle the older schema or tell users to run a full `/codebase-tutorial:write`.

## Cutting a release

Do these in **one commit**:

1. In `CHANGELOG.md`, rename `## Unreleased` to `## X.Y.Z`, and start a new empty `## Unreleased` above it if you like.
2. Set `"version": "X.Y.Z"` in `.claude-plugin/plugin.json`.
3. In `skills/update/templates/tutorial-freshness.yml`, set `PLUGIN_REF: vX.Y.Z`. (The tag will point at this very commit, so the template always names a tag that exists.)
4. Check for stale version mentions: `grep -rn "v[0-9]\+\.[0-9]\+\.[0-9]\+" --include=*.md --include=*.yml .`

Then:

5. `git push`
6. Tag that commit and push the tag: `git tag vX.Y.Z && git push origin vX.Y.Z`
7. Publish a GitHub release for the tag, pasting the changelog section as the notes.

## Before releasing

- Run the checkers against any sample tutorial you have: `python skills/write/scripts/check_tutorial.py --repo <repo> --tutorial <tutorial dir>`.
- If you have the `claude` CLI: `claude plugin validate .`
- Try a real run with `claude --plugin-dir .` on a small repo.

## How users upgrade

```
/plugin marketplace update bergam0t
/plugin update codebase-tutorial@bergam0t
```

Tutorials generated by an older version keep working with `/codebase-tutorial:update`, which reads the version recorded in `_generation.json`.
